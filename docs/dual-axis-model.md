# 双轴认知模型

FinanceOS 的核心创新：将财务工作抽象为「角色×生命周期」的矩阵模型。

## 为什么是双轴？

传统的 AI prompt 工程是线性的——"先做 A，再做 B，最后做 C"。但真实的财务工作不是线性的：同一个任务（如月度分析）需要多个角色（取数的、分析的、写报告的）在多个阶段（感知、研判、执行）中并行或串行协作。

**双轴模型 = 把任务中的"谁 + 做什么 + 什么时候"一次性编排清楚。**

## 横轴：角色轴（Who × What）

```
数据分析师 ─── 报告撰写员 ─── 知识管家
     │               │              │
   取数归因        套模板出稿      经验入库
   异常检测        脱敏格式        版本管理
   勾稽校验        报送输出        库维护
```

角色分为**核心（常驻）**和**按需（动态加载）**：

| 类型 | 角色 | 何时激活 |
|------|------|---------|
| 核心 | 数据分析师 | 始终在线 |
| 核心 | 报告撰写员 | 始终在线 |
| 核心 | 知识管家 | 沉淀阶段激活 |
| 按需 | 预算管控官 | 涉及预算时加载 |
| 按需 | 政策研究员 | 涉及政策法规时加载 |

## 纵轴：生命周期（When × How）

```
感知 ──→ 研判 ──→ 执行(校验) ──→ 交付 ──→ 沉淀
 │          │          │            │         │
取数      归因判断    起草编制    脱敏报送   经验入库
异常标注  分色定级    勾稽校验    STOP gate  决策记录
```

每个阶段有明确的门槛条件：

| 阶段 | 进入条件 | 退出条件 |
|------|---------|---------|
| 感知 | 任务启动 | 异常标注清单完成 |
| 研判 | 异常标注完成 | 分色定级 + 归因完成 |
| 执行 | 研判完成 | 报告初稿 + 四维校验通过 |
| 交付 | 校验通过 | STOP gate 放行 |
| 沉淀 | 交付完成 | 经验/决策入库 |

## 矩阵 = 工位

交叉点形成**工位**——特定角色在特定阶段要做的事：

```
              感知      研判      执行      交付      沉淀
数据分析师    📊取数    📊归因    📊校验     —         —
报告撰写员     —        —       ✍️出稿    ✍️脱敏     —
知识管家       —        —        —         —        📚入库
```

编排一个任务 = 在矩阵上画一条路径。

## 示例：月度经营分析路径

```
数据分析师(感知) → 数据分析师(研判) → 报告撰写员(执行) → 数据分析师(校验)
      ↓                                        ↓
   取数+异常标注                          报告撰写员(交付)
                                          知识管家(沉淀)
```

这就是 L2.5 任务模板 `monthly-budget-analysis` 的编排逻辑。

---

## 与传统 prompt 工程的对比

| 维度 | 传统 Prompt | 双轴模型 |
|------|-----------|---------|
| 结构 | 线性指令列表 | 矩阵式编排 |
| 复用 | 每次重写 | L2.5 任务模板一次编排反复调用 |
| 校验 | 依赖人工检查 | 四维校验自动执行 |
| 角色切换 | AI 自行判断 | 明确角色边界和接力契约 |
| 知识积累 | 无 | L3 案例库 + L4 决策日志沉淀 |
| Token 效率 | 全量加载 | 三级加载，省 65-70% |
