# FinanceOS 三库框架规范 v1.0

> 本规范定义三库+一区的**框架规则**：目录结构、库间引用、准入规则、更新规则、与技能的衔接机制。
> 具体内容（脱敏清单各项、权限分级各级、模板各章节）作为初版示例已录入，使用中边用边调整，不作为当前审阅重点。
> **本文件才是当前要审的"框架"本身。**

---

## 一、目录结构（已就位）

> `{FINANCEOS_KB_ROOT}` = 知识库根目录（仓库内默认 `./kb/`；各平台部署路径见 `docs/getting-started.md` 平台对照表）

```
{FINANCEOS_KB_ROOT}/
├── L1-rules/              # 存规则：脱敏、权限、口径、格式
├── L2-templates/          # 存模板：报告骨架、表格结构
├── L2.5-task-templates/   # 存任务编排模板：高频任务的预设路径
├── L3-cases/             # 存经验：历史任务的处理经验
├── L4-decision-logs/      # 存决策：重要决策的上下文与结果
└── data-buffer/          # 只读即弃：任务进行中的临时数据
```

**铁律**：一个实体只进一个库。交叉用**引用**，禁止复制。
- 例：月度分析模板在 L2；其中引用的脱敏规则在 L1；不把脱敏规则复制进模板。

## 二、各库定位与边界

| 库 | 存什么 | 不存什么 | 生命周期 |
|----|--------|---------|---------|
| **L1 规则库** | 脱敏标准、权限分级、口径定义、格式规范 | 具体数据、具体任务、具体案例 | 长期稳定，有版本号 |
| **L2 模板库** | 报告骨架、表格结构、文档格式 | 规则、案例、决策 | 有版本号，按需更新 |
| **L2.5 任务模板库** | 高频任务的预设编排路径（角色×生命周期路径） | 具体内容、具体数据 | 随任务沉淀，高频的固化 |
| **L3 案例库** | 历史任务的处理经验（问题→方法→结果→可复用点） | 规则、模板、原始数据 | 使用中边用边填，冷启动可空 |
| **L4 决策日志** | 重要决策的上下文、选项、结果、复盘 | 日常查询、过程数据 | 按决策沉淀，Gate-H (strict) 全量 |
| **数据缓冲区** | 任务进行中的临时取数、中间产物 | 任何需要长期保留的东西 | 任务结束即弃，不跨会话 |

## 三、库间引用关系

```
L1规则 ──被引用──> L2模板（模板内引用脱敏规则/格式规范）
L1规则 ──被引用──> L2.5任务模板（任务路径中标注用哪条规则）
L2模板 ──被引用──> L2.5任务模板（任务路径中标注产出套哪个模板）
L3案例 ──被引用──> 研判阶段（归因判断时引历史经验）
L4决策 ──被引用──> 研判阶段（判断时引历史决策上下文）
L2.5任务模板 ──命中即跳过──> 意图识别（匹配到模板直接走预设路径）
数据缓冲区 ──只读──> 各阶段（取数/中间产物传递，不落库）
```

**引用方式**：文件名 + 锚点。例：`[L1:脱敏标准清单#水务专项-水费数据]`。
不复制内容，只记引用路径。

## 四、内容准入规则

### L1 规则库准入
- **准入条件**：可复用、跨任务稳定、有明确判断标准
- **准入流程**：起草 → 财务总监确认 → 入库（带版本号）
- **当前初版**：脱敏标准清单 v1、权限分级 v1（已录入，可调整）

### L2 模板库准入
- **准入条件**：高频使用、格式可固化、有公文/财务规范依据
- **准入流程**：起草 → 套用验证 → 入库（带版本号）
- **当前初版**：月度经营分析模板 v1（已录入，可调整）

### L2.5 任务模板库准入
- **准入条件**：同一类任务出现≥3次、编排路径稳定可复用
- **准入流程**：任务跑通 → 提炼路径 → 入库
- **当前**：空启动，使用中积累

### L3 案例库准入
- **准入条件**：任务完成后，有可复用的"问题→方法→结果"经验
- **准入流程**：任务沉淀阶段自动提取 → 知识管家审核 → 入库
- **当前**：空启动，使用中积累

### L4 决策日志准入
- **准入条件**：Gate-H/Gate-H (strict) 风险等级任务的决策点
- **准入流程**：STOP gate 通过时自动记录 → 入库
- **当前**：空启动，使用中积累

### 数据缓冲区
- **准入条件**：无。任务进行中临时存放，结束即弃
- **跨会话**：不保留

## 五、内容更新规则

| 库 | 谁更新 | 更新触发 | 版本管理 |
|----|--------|---------|---------|
| L1 | 财务总监确认后由 AI 录入 | 规则变化、规范更新、发现漏洞 | 主版本号变更 |
| L2 | AI 起草 → 财务总监确认 | 格式规范变、章节调整、套用发现问题 | 主版本号变更 |
| L2.5 | AI 提炼 → 财务总监确认 | 同类任务≥3次、路径优化 | 新增条目 |
| L3 | AI 自动提取 → 知识管家审核 | 每次任务沉淀阶段 | 追加条目 |
| L4 | STOP gate 触发自动记录 | 每次 Gate-H/Gate-H (strict) 决策 | 追加条目 |

**更新原则**：存逻辑不存事实。规则库存判断逻辑，不存具体数据；案例库存方法论，不存原始数据。

## 六、与技能（cfo-command-center v2.4.1）的衔接机制

### 技能调用库的方式

技能在运行闭环的各阶段，按需加载对应库：

```
感知阶段    → 读数据缓冲区（取数）
研判阶段    → 读 L3 案例库 + L4 决策日志（引历史）
执行阶段    → 读 L2 模板库 + L2.5 任务模板库（套骨架）+ L1 规则库（引规则）
校验收尾    → 读 L1 规则库（勾稽/脱敏/格式校验依据）
交付阶段    → 读 L1 规则库（脱敏方案/权限校验）
沉淀阶段    → 写 L3 案例库 + L4 决策日志 + L2.5 任务模板库
```

### Token 三级加载（与技能规程一致）

- **内核层**：技能本体（SKILL.md）——常驻
- **场景层**：L1 规则库相关条目——按任务类型加载
- **工作层**：L2 模板 + L2.5 任务模板 + L3 案例 + L4 决策——按阶段按需加载

### 库目录路径约定

技能通过固定路径访问库：
```
{FINANCEOS_KB_ROOT}/L1-rules/
{FINANCEOS_KB_ROOT}/L2-templates/
{FINANCEOS_KB_ROOT}/L2.5-task-templates/
{FINANCEOS_KB_ROOT}/L3-cases/
{FINANCEOS_KB_ROOT}/L4-decision-logs/
{FINANCEOS_KB_ROOT}/data-buffer/
```
