## 一、系统概览

### 1.1 这是什么

FinanceOS V2.4 是为市属水务国企财务总监设计的 AI 认知操作系统。它不是单一工具，而是一套"调度中枢 + 知识底座 + 运行闭环"的工作体系：

- **调度中枢**：`cfo-command-center` 技能（AI 财务办公室主任 + 主动认知雷达）
- **知识底座**：3+2 库（L1 规则 / L2 模板 / L2.5 任务模板 / L3 案例 / L4 决策日志 + 数据缓冲区）
- **运行闭环**：感知 → 研判 → 执行(含校验) → 交付 → 沉淀，五阶段串行

### 1.2 物理架构

```

└── financeos-kb/                               # 知识库（内容底座）  ~128KB  ← 仓库 kb/
    ├── README.md                                 # KB 索引
```

### 1.3 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| 双轴模型 | 横轴=角色(5个)，纵轴=生命周期(5阶段)，交叉点=工位 |
| Step0 模式判别 | 任务进来先判：轻量 / 完整 / 紧急，决定走多重的流程 |
| STOP gate | 关键决策点必须人工确认，AI 不能自行通过 |
| 3+2 库 | 3 个规则/模板库 + 2 个积累库 + 1 个缓冲区 |
| Token 三级加载 | 内核(常驻) → 场景(按任务) → 工作(即弃)，省 65-70% Token |
| 主动认知层 | 只发现不决策，巡检异常后"敲门不开门" |

## 二、使用逻辑

### 2.1 任务进入系统的完整路径

```
你发一句话
  ↓
Step0 模式判别（3秒内完成）
  ├─ 紧急信号词 AND 产出物意图 → 紧急通道（最简路径，事后补归档）
  ├─ 有产出物意图，无紧急信号词 → 完整模式（启动角色编排全流程）
  └─ 无产出物意图 → 轻量模式（直接回答，不编排）
  ↓
路由调度（4层）
  1. 意图识别 + 消歧（命中 L2.5 模板则跳过）
  2. 任务分解（拆子任务，排依赖）
  3. 双轴编排（在角色×生命周期矩阵上画路径）
  4. STOP gate + 协作模式（按风险等级匹配）
  ↓
五阶段执行
  感知 → 研判 → 执行(含校验) → 交付 → 沉淀
  ↓
产出物交付 + 经验入库
```

### 2.2 三种模式触发逻辑

| 模式 | 触发条件 | 走的流程 | 适用场景 |
|------|---------|---------|---------|
| 轻量模式 | 无"产出物"信号词（看看/查一下/多少） | 直接执行，不启动角色编排 | "上个月产销差率多少？" |
| 完整模式 | 有"产出物"信号词，无紧急信号词 | 五阶段全流程 | "写6月预算执行分析报告" |
| 紧急通道 | 紧急信号词 AND 产出物意图，双条件同时满足 | 最简路径：取数→简单归因→输出 | "领导马上要预算差异分析" |

**关键修正点**：单字"快""赶"不触发紧急通道。"数据涨得快"是轻量模式，"快点要预算分析"才是紧急通道。

### 2.3 五阶段闭环详解

| 阶段 | 谁干 | 干什么 | 用什么库 | 产出什么 |
|------|------|--------|---------|---------|
| 感知 | 数据分析师 | 取数 + 阈值比对 + 异常标注 | L1 anomaly-thresholds | 异常标注清单 |
| 研判 | 数据分析师 | 分色定级 + 归因深度判定 | L3 案例 + L4 决策 | 预警汇总表 |
| 执行 | 报告撰写员 | 套模板出稿 + 校验收尾 | L2 模板 + L2.5 任务模板 + L1 规则 | 报告初稿 |
| 交付 | 报告撰写员 | 脱敏 + 格式转换 + STOP gate | L1 脱敏标准 + 权限分级 | 最终交付物 |
| 沉淀 | 知识管家 | 经验入 L3 / 决策入 L4 / 模板入 L2.5 | L3 + L4 + L2.5 | 更新的库条目 |

**校验是执行阶段的收尾步骤**（不是独立阶段），四维校验：勾稽 / 异常 / 口径 / 格式。校验不通过≤2轮回退修正，>2轮停下报告。

### 2.4 风险等级与协作模式（STOP Gate 四级）

| Gate | 协作模式 | gate 强度 | 审计三段 | 触发 L4 |
|------|---------|----------|---------|---------|
| Gate-L 日常查询 | 委托 | 异常才报 | 不输出 | 否 |
| Gate-M 分析研究 | 标准 | 关键节点 | 不输出 | 否 |
| Gate-H 预算/报送 | 标准 | +数据校验+脱敏 | 简版 | **强制** |
| Gate-H 审计/巡视（严格子级） | 紧控 | 每步 gate + 决策日志 | 完整 | **全量** |
| Gate-X 禁止 | 拒绝执行 | — | — | — |

> v2.4：原 T1/T2/T3/T4 细化为 Gate-L/M/H/X。原 T4（审计巡视）归入 Gate-H 严格子级；新增 Gate-X 禁止级（删除/修改原始数据）。

**预设方案**（V2.2 引入，减少打断）：
- 内部分析默认：不脱敏、不输出审计三段、分析决策预设阈值自动执行
- 对外报送默认：全脱敏、输出简版审计三段、判断决策必停

### 2.5 阈值预警三级分色

| 颜色 | 触发条件 | AI 动作 | 需人工确认 |
|------|---------|---------|-----------|
| 黄色 | 单月超阈值，前2月正常 | 报告中标注 + 简要归因 | 否 |
| 橙色 | 连续2月同方向 / YTD累计偏离 | 主动通知 + 深度归因 + 趋势预测 | 建议确认 |
| 红色 | 连续3月同方向 | 强制通知 + 预暂停 + 仅汇总 | **必须确认** |

**特殊规则**：旺季(6-9月)电费/药剂费季节性豁免降一级；政策性调整降级；大额一次性剥离；化债专项单独追踪。

## 三、新会话启动

### 3.1 标准启动指令

每次新开会话，对 AI 说：

```
加载 cfo-command-center 技能，读 {FINANCEOS_KB_ROOT}/README.md，继续 V2.4 推进
```

AI 会自动完成：
1. 加载技能（调度逻辑入内核层）
2. 读取 KB README（了解库状态和文件索引）
3. 加载当前阶段所需的 L1/L2 规则和模板

### 3.2 快速启动（日常使用）

如果只是跑日常分析任务，不需要推进框架，直接说：

```
加载 cfo-command-center 技能，然后帮我做月度预算执行分析
```

技能加载后，AI 会自动按 L2.5 任务模板的编排路径执行。

### 3.3 启动检查清单

| 检查项 | 方法 | 预期结果 |
|--------|------|---------|
| 技能是否加载 | 问 AI "当前加载了什么技能" | 回答含 cfo-command-center v2.4 |
| 知识库是否可读 | 问 AI "L1 有哪些文件" | 列出 data-masking / permission-tiers / anomaly-thresholds 等 |
| L2.5 模板是否就位 | 问 AI "月度预算执行分析模板版本" | monthly-budget-analysis.md |
| L3 案例数 | 问 AI "案例库有几条" | 11条 |

## 四、场景操作指南

### 4.1 场景A：月度预算执行分析（最高频）

**触发时机**：月末结账后 / 总监要求 / 主动认知层月度巡检触发

**操作步骤**：

1. **准备数据**：把月度预算+实际数据整理好（表格/JSON/口述均可）
   - 必须有：当月预算 vs 实际（全部科目）
   - 最好有：前2个月实际数据（用于趋势判定）
   - 如有：化债进度/补贴拨付/政策变动/突发事件

2. **对 AI 说**：
   ```
   加载 cfo-command-center 技能，这是[月份]预算执行数据，帮我做月度预算执行分析
   [附数据]
   ```

3. **AI 自动执行五阶段**：
   - 感知：数据入缓冲区 → 读 L1 阈值比对 → 产出异常标注清单
   - 研判：按判定矩阵分色 → 检查特殊规则（旺季/政策/一次性/化债/补贴）→ 确定归因深度
   - 执行：套 L2 月度模板出稿 → 四维校验（勾稽/异常/口径/格式）
   - 交付：Gate-M 内部分析默认不脱敏，直接交付
   - 沉淀：经验入 L3，检查阈值调整建议

4. **预期产出**：
   - 月度预算执行分析报告（Markdown，八章节）
   - 异常标注清单（中间产物，存缓冲区）
   - L3 案例（沉淀阶段自动产出）

5. **预期耗时**：15-20分钟（含校验），1轮校验通过为正常基线

**数据格式参考**（JSON，每项含预算/实际/差异/差异率）：
```json
{
  "meta": { "数据期": "2026年7月", "数据来源": "财务系统导出" },
  "水量": { "供水量": {"预算": 850, "实际": 880, "单位": "万m³"}, ... },
  "成本_制水": { "电费": {"预算": 420, "实际": 465, "差异": 45, "差异率": "10.7%"}, ... },
  ...
}
```

### 4.2 场景B：季度财务分析

**触发时机**：季末结账后

**操作步骤**：

1. **准备数据**：季度3个月数据 + 去年同期数据（用于同比）
2. **对 AI 说**：
   ```
   加载 cfo-command-center 技能，这是Q3季度数据，帮我做季度财务分析
   [附数据]
   ```
3. **AI 自动执行**：与月度类似，但增加：
   - 同比分析（去年同期对比）
   - 趋势研判（连续季度黄→橙→红）
   - 季节性供水特征分析
   - YTD 累计执行率 vs 时间进度
   - 全年预算完成预测
4. **引用模板**：`[L2:季度财务分析报告模板v1]`
5. **注意**：季度分析时阈值口径要先做月度分项标注再汇总，不直接对合计数做绝对值判定

### 4.3 场景C：专项财务分析

**触发时机**：化债注资 / 水价调整 / 重大投资 / 资产处置等专项事项

**操作步骤**：

1. **对 AI 说**：
   ```
   加载 cfo-command-center 技能，帮我做[专项名称]专项财务分析
   背景：[简述事项背景]
   数据：[附相关数据]
   ```
2. **AI 自动套用** `[L2:专项财务分析报告模板v1]`，六章节：背景→现状→分析→风险评估→建议→附件
3. **适配指引**（AI 自动匹配）：
   - 化债注资：置换债务明细、利息节约测算、资产负债率改善
   - 水价调整：调价影响测算、成本补偿充分性、社会稳定风险
   - 重大投资：NPV/IRR/回收期、现金流影响、投后管理
   - 资产处置：处置损益测算、国资流失风险、审批合规
4. **风险等级**：专项分析默认 Gate-H（对外报送级），需要脱敏 + 审计三段

### 4.4 场景D：日常查询

**操作**：直接问，不需要加技能前缀（但建议先加载技能以获得专业判断）

```
加载 cfo-command-center 技能
上个月产销差率多少？跟预算比差多少？
```

AI 走轻量模式，直接回答，不启动五阶段编排。

### 4.5 场景E：紧急任务

**操作**：在指令中包含紧急信号词 + 产出物意图

```
加载 cfo-command-center 技能，领导马上要预算差异分析，快出一份
```

AI 走紧急通道：取数 → 简单归因 → 输出（标注"紧急初稿，未经完整校验"），事后补归档。

**注意**：紧急通道产出物未经四维校验，正式使用前建议补跑完整模式。

## 五、库管理操作

### 5.1 L1 规则库调整

**何时调整**：
- 阈值数值不匹配实际（偏松/偏紧）
- 新增科目需要设阈值
- 政策变化导致规则需要修改

**操作流程**：
```
1. AI 在分析中发现阈值问题 → 提出调整建议
2. 总监确认调整方案
3. 对 AI 说："更新 L1 anomaly-thresholds，[具体调整内容]"
4. AI 修改文件，更新版本号（v1.1 → v1.2）
5. 记录调整前后值、调整原因、确认人
```

**校准周期**：
| 维度 | 频率 | 触发条件 |
|------|------|---------|
| 初始校准 | 入库后首次使用 | 对比实际数据验证 |
| 季度校准 | 每季度末 | 根据偏离分布调整 |
| 年度校准 | 年度预算编制时 | 按新年度预算口径统一调整 |

### 5.2 L2 模板库更新

**何时更新**：格式规范变化、章节调整、套用发现问题

**操作流程**：
```
1. 对 AI 说："更新 L2 monthly-analysis，[具体修改内容]"
2. AI 修改文件，更新版本号
3. 下次使用自动套用新版本
```

### 5.3 L2.5 任务模板固化

**当前状态**：monthly-budget-analysis.md（基于 2 次运行提炼）

**升版条件**：
1. 第 3 次月度预算执行分析运行完成
2. 编排路径与 v0.9 一致（无重大偏差）→ 直接升 v1.0
3. 编排路径有调整 → 更新模板后升 v1.0

**操作**：
```
1. 跑第 3 次月度预算执行分析（真实数据）
2. 对 AI 说："对比本次运行路径与 L2.5 模板，有偏差吗？"
3. 无偏差 → "升版 L2.5 monthly-budget-analysis 到 v1.0"
4. 有偏差 → 先更新模板再升版
```

### 5.4 L3 案例库入库

**自动入库**：每次任务完成后的沉淀阶段，AI 自动提炼经验写入 L3

**手动触发**：
```
对 AI 说："把刚才这次分析的经验写入 L3 案例库"
```

**入库标准**（满足任一）：
- 用了与现有条目不同的方法且效果好
- 发现新异常模式
- 编排逻辑与现有模板不同且可复用
- 决策事后验证与预期不一致（反面经验）

**不入库**：与现有完全重复 / 纯机械操作 / 未验证的外部原文

### 5.5 L4 决策日志记录

**自动触发**：Gate-H 任务的 STOP gate 通过时自动记录

**手动触发**：
```
对 AI 说："这个决策记录到 L4，[决策内容]"
```

**记录格式**：`DEC-YYYYMMDD-序号_决策事项简述.md`

**文件命名示例**：`DEC-20260730-001_月度预算执行差异容忍度调整.md`

## 六、备份与维护

### 6.1 备份对象

| 对象 | 路径 | 大小 | 重要性 |
|------|------|------|--------|
| 技能 | `{FINANCEOS_SKILL_DIR}/` | ~12KB | 高（调度逻辑核心） |
| 知识库 | `{FINANCEOS_KB_ROOT}/` | ~128KB | 高（积累的经验和规则） |
| 缓冲区 | `{FINANCEOS_KB_ROOT}/data-buffer/` | 可变 | 低（临时数据，可不备份） |

**总备份量**：约 140KB，极小，每次全量备份即可。

### 6.2 全量备份（推荐每周或重大变更后）

**备份命令**（在 Bash 中执行）：

```bash
# 创建带时间戳的备份目录
BACKUP_DIR="D:/1_Documents/AiWorkSpace/financeos-backup/$(date +%Y%m%d_%H%M%S)"
mkdir -p "$BACKUP_DIR"

# 备份技能
cp -r {FINANCEOS_SKILL_DIR}/ "$BACKUP_DIR/cfo-command-center/"

# 备份知识库（含缓冲区）
cp -r {FINANCEOS_KB_ROOT}/ "$BACKUP_DIR/financeos-kb/"

# 验证备份
echo "=== 备份验证 ==="
find "$BACKUP_DIR" -type f | wc -l
echo "文件已备份到: $BACKUP_DIR"
```

**备份策略说明**：
- 备份到 `D:/1_Documents/AiWorkSpace/financeos-backup/` 目录
- 每次备份创建带时间戳的子目录，不覆盖旧备份
- 预计每次备份 ~140KB，保留最近 10 次即可（约 1.4MB）

## 七、故障排查

### 7.1 技能未加载

**现象**：AI 回答不符合财务总监指挥台的风格，不引用 L1/L2 规则

**排查**：
1. 确认技能文件存在：`ls {FINANCEOS_SKILL_DIR}/SKILL.md`
2. 重新发送启动指令：`加载 cfo-command-center 技能`
3. 如果文件不存在，从备份恢复

### 7.2 知识库文件找不到

**现象**：AI 说"L1 anomaly-thresholds 不存在"或引用路径错误

**排查**：
1. 检查目录结构：`find {FINANCEOS_KB_ROOT}/ -type f`
2. 确认文件名无误（中文文件名，注意编码）
3. 如果文件丢失，从备份恢复

### 7.3 阈值判定异常

**现象**：所有科目都标黄色 / 所有科目都不触发

**排查**：
1. 检查数据格式是否正确（预算/实际/差异/差异率是否齐全）
2. 检查阈值数值是否适合公司体量（当前基于中型水务企业估算）
3. 对 AI 说："检查 L1 anomaly-thresholds，[科目]的阈值是否合理？"
4. 如需调整，按 5.1 节流程操作

### 7.4 校验反复不通过

**现象**：报告校验 >2 轮仍不通过

**排查**：
1. 检查数据勾稽关系（收入差异Σ = 成本差异Σ + 利润差异）
2. 检查是否有遗漏的科目或特殊事项未标注
3. 对 AI 说："校验不通过，列出具体不通过的检查项"
4. 修正数据后重跑

### 7.5 缓冲区数据残留

**现象**：缓冲区文件过多，影响新任务

**处理**：缓冲区设计为即弃，可安全清理：
```bash
# 清理缓冲区（保留目录结构）
rm -rf {FINANCEOS_KB_ROOT}/data-buffer/input/*
```

**注意**：清理前确认没有正在进行的任务。缓冲区数据不跨会话保留，清理不影响知识库。
