# 异常阈值标准

> 效力等级：L1 强制约束 · 红线不可违反
> 适用：FinanceOS 感知阶段异常检测 + 研判阶段差异归因 + 主动认知层巡检
> 版本：v1.1 · 2026-07-30（case002/003验证后补充规则3/4/5/6）
> 关联：cfo-command-center v4.1 第3节Step0(紧急通道) + 第5节(主动认知层)

---

## 一、设计原则

1. **双轨触发**：每个科目设「绝对值阈值 + 相对比例阈值」，满足其一即触发标注
2. **分维度判定**：月度波动 / 累计偏离 / 连续趋势，三个维度独立判定再综合
3. **分色预警**：黄(关注) → 橙(预警) → 红(强制人工确认)，颜色决定后续动作
4. **阈值可调**：以下数值为建议初始值，按公司实际体量调整；调整需财务总监确认后入库
5. **阈值不等于紧急通道**：阈值预警是研判依据，不是紧急信号；紧急通道触发见第六节

## 二、核心财务指标阈值（保留+细化）

| 指标 | 触发阈值 | 黄色(一次性) | 橙色(趋势性) | 红色(结构性) |
|------|---------|-------------|-------------|-------------|
| 产销差率偏离预算 | >0.5pp | 单月超阈值，前2月正常 | 连续2月同方向偏离 | 连续3月同方向偏离 |
| 水费回收率偏离预算 | >2pp | 同上 | 同上 | 同上 |
| 经营现金流净额偏离 | >预算15%或±200万 | 同上 | 同上 | 同上 |
| 利润总额偏离预算 | >10% | 同上 | 同上 | 同上 |
| 资产负债率偏离年末目标 | >2pp | 同上 | 同上 | 同上 |

**说明**：核心指标为综合指标，偏离反映全局性问题，阈值相对收紧。

## 三、成本科目分项阈值（水务专项）

> 按水务企业标准成本科目结构编制。绝对值阈值为月度差异口径。
> 初始值基于中型水务企业（月营收 3000-8000 万）经验估算，使用前需按本公司实际校准。

### 3.1 制水成本

## 四、一次性 vs 趋势性判定规则

### 4.1 判定矩阵

| 状态 | 月度偏离 | 前2月情况 | 判定 | 颜色 | 后续动作 |
|------|---------|----------|------|------|---------|
| A | 超阈值 | 正常（未超阈值） | 一次性波动 | 🟡 黄色 | 标注+归因，不升级 |
| B | 超阈值 | 1月超阈值（同方向） | 趋势性变化 | 🟠 橙色 | 预警通知+深度归因 |
| C | 超阈值 | 2月连续超阈值（同方向） | 结构性变化 | 🔴 红色 | 强制人工确认+考虑调整预算基准 |
| D | 未超月度阈值 | YTD累计偏离>年度预算3% | 累计偏离 | 🟠 橙色 | 预警通知+趋势分析 |

### 4.2 特殊规则

1. **季节性豁免**：供水旺季（6-9月）电费、药剂费波动超阈值但在历史同期正常范围内的，降一级处理（橙→黄、红→橙）
2. **政策性调整**：水价调整/电价调整/税率变化导致的偏离，标注「政策性」后降级，不计入趋势判定
3. **大额一次性**：单笔>50万（大型企业）或>15万（中型水务企业，月营收3000-8000万）的非经常性支出（如大修、资产处置），单独标注「一次性」，不参与趋势判定；单笔10-15万且非经常性的，标注「一次性·小额」便于归因但不剥离
4. **化债专项**：化债注资/置换导致的利息支出变化，标注「化债」后单独追踪，不与常规利息合并趋势判定；建议维护「化债置换进度台账」（月度置换金额/利率变化/节约利息），便于环比和累计效果测算
5. **补贴延迟**：政府补贴延迟拨付导致的收入差异，剥离后单独标注「时间性差异」，不影响利润趋势判定；季度/年度分析必须执行补贴剥离（不能仅标注）
6. **阈值口径**：本标准阈值以月度为基础口径；季度/年度分析时，先做月度分项标注再汇总趋势，不直接对合计数做绝对值阈值判定（比例阈值可跨期适用）

### 4.3 趋势判定数据需求

- 判定「连续N月」需至少前3个月的预算执行数据
- 数据不足（<3月）时，只做月度标注（黄色），不做趋势判定
- YTD累计偏离从每年1月起累计

## 五、预警分级与动作映射

| 颜色 | 触发条件 | 通知方式 | AI 可执行动作 | 需人工确认 |
|------|---------|---------|-------------|-----------|
| 🟡 黄色 | 单月超阈值 | 报告中标注 | 归因分析+建议 | 否 |
| 🟠 橙色 | 连续2月同方向 / YTD累计偏离 | 主动通知总监 | 深度归因+趋势预测+改进建议 | 建议确认 |
| 🔴 红色 | 连续3月同方向 | 强制通知+预暂停 | 仅汇总数据+标注，不自动出结论 | 必须确认（考虑调预算基准） |

**关键约定**：
- 黄色标注在报告中自然呈现，不打断流程
- 橙色预警主动推送通知，但在内部分析场景下不强制打断
- 红色预警在任何场景下都需人工确认后才继续

## 六、与紧急通道的联动规则

> 解决第一档遗留的「紧急通道假阳性」问题。

### 6.1 紧急通道触发条件（修正）

紧急通道 = **紧急信号词** AND **产出物意图**，两者同时满足才触发：

| 条件 | 说明 |
|------|------|
| 紧急信号词 | 马上/立刻/领导要/巡视组问/紧急/急/今天要/尽快 |
| 产出物意图 | 写报告/出材料/分析/报送/汇总/编制/做表 |

**修正要点**：
- ~~"快"~~ 单独不触发（"数据涨得快"≠紧急任务）；仅在"要得快""快点出"组合语境中触发
- ~~"赶"~~ 单独不触发（"赶进度"≠紧急任务）；仅在"赶着要""赶材料"组合语境中触发
- 纯紧急信号词无产出物意图 → 轻量模式优先处理（不禁门，但排前面）
- 产出物意图无紧急信号词 → 完整模式正常编排

### 6.2 阈值预警与紧急通道的关系

| 场景 | 触发紧急通道？ | 说明 |
|------|--------------|------|
| 红色预警（结构性变化） | 否，但强制人工确认 | 阈值预警走研判流程，不走紧急通道 |
| 红色预警 + 总监说"快出分析" | 是 | 预警+紧急信号词+产出物意图 |
| 黄色标注 + 日常分析 | 否 | 正常流程 |
| 橙色预警 + 巡视组问 | 是 | 预警+巡视组信号词 |

### 6.3 紧急通道的简化路径

触发后走最简路径：取数 → [简单归因] → 输出（标注"紧急初稿，未经完整校验"），事后补归档。

## 七、校准与更新

| 维度 | 规程 |
|------|------|
| 初始校准 | 入库后首次使用时，对比实际数据验证阈值合理性 |
| 季度校准 | 每季度末根据实际偏离分布，调整明显偏松/偏紧的阈值 |
| 年度校准 | 年度预算编制时，根据新年度预算口径统一调整 |
| 调整流程 | AI 提建议 → 财务总监确认 → 入库（版本号变更） |
| 调整记录 | 记录调整前后值、调整原因、确认人 |

## 八、与技能的衔接

```
感知阶段    → 读本标准，对缓冲区数据做分科目阈值比对 → 产出异常标注清单
研判阶段    → 读异常标注清单 + 4.x判定规则 → 确定颜色等级 → 决定归因深度
Step0判别   → 读6.x紧急通道规则 → 判定模式（紧急/轻量/完整）
主动认知层  → 读本标准做巡检 → 触发对应颜色预警 → 按五节动作映射执行
```
