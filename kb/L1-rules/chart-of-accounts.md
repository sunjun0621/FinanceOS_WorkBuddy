> 效力等级：L1 强制约束 · 红线不可违反

## 一、说明

科目编码基线是 AI 助手进行财务数据分析时的科目体系基准。其核心作用：

1. **口径校验**：每次导入新数据时，与基线比对，识别科目新增、缺失、名称变更或层级调整
2. **一致性保障**：确保不同期间、不同报表的科目口径一致，避免因科目变动导致分析失真
3. **差异溯源**：科目变动时，记录变动情况并提示用户确认，防止隐性口径偏差

**适用范围**：预算执行分析、财务报表分析、对外报送数据校验等所有涉及科目体系的数据处理场景。

## 三、口径一致性检查规则（四级检查）

每次导入新期间数据时，AI 助手须执行以下口径一致性检查，比对导入数据与基线科目表：

| 检查级别 | 检查类型 | 检查规则 | 触发条件 | 处置方式 |
|----------|----------|----------|----------|----------|
| 第1级 | 新增科目 | 导入数据中存在基线表中没有的科目编码 | 科目编码不在基线表中 | 记录新增项，提示用户确认是否更新基线 |
| 第2级 | 缺失科目 | 基线表中存在但导入数据中没有的科目 | 基线科目编码未出现在导入数据中 | 记录缺失项，提示用户确认：科目取消/合并/本期无发生额 |
| 第3级 | 名称变更 | 同一科目编码的名称与基线不一致 | 编码相同但名称文本不同 | 记录变更项，提示用户确认名称变更并更新基线 |
| 第4级 | 层级变更 | 同一科目编码的层级与基线不一致 | 编码相同但层级（一级/二级/三级）不同 | 记录变更项，提示用户确认层级调整并更新基线 |

### 检查结果分级

| 结果等级 | 定义 | 处置 |
|----------|------|------|
| 通过 | 无任何差异 | 继续分析流程 |
| 提示 | 存在新增或缺失科目，但不影响核心分析 | 记录差异，继续分析，报告中注明口径差异 |
| 警告 | 存在名称变更或层级变更 | 暂停分析，提示用户确认后继续 |
| 阻断 | 差异数量超过总科目的20%，或核心科目缺失 | 触发 STOP Gate，暂停全部分析流程 |

## 四、STOP Gate 规则

### STOP Gate：科目口径阻断（S-Subject）

**触发条件**（满足任一即触发）：
- 口径一致性检查结果为"阻断"
- 核心科目（资产合计、负债合计、收入合计、支出合计、净利润等）缺失
- 科目差异数量超过总科目的 20%

**检查项**：
- [ ] 用户已确认科目变动原因（制度调整 / 软件升级 / 数据错误）
- [ ] 基线科目表已更新或用户确认按现有基线继续
- [ ] 差异科目已在报告中标注

**未通过处置**：暂停分析流程，向用户报告差异详情，请求确认后继续。

## 五、键名匹配规则（三级回退）

### 5.1 问题背景

用友、金蝶等财务软件导出的报表文件（Excel/CSV）可能包含全角引号、中文空格（U+3000）、不可见字符（BOM、零宽空格）等特殊字符，导致程序化读取时键名与预期不匹配，进而引发数据解析失败或科目遗漏。

### 5.2 匹配策略

AI 助手在匹配科目键名时，按以下顺序执行三级回退匹配：

| 匹配级别 | 匹配方式 | 说明 |
|----------|----------|------|
| 第一级：精确匹配 | 严格相等比较 | 字符串完全一致，包括空格和标点 |
| 第二级：去空格匹配 | 去除全角/半角空格、不可见字符后比较 | 处理中文空格（U+3000）、BOM、零宽空格等 |
| 第三级：关键词包含 | 去除标点符号后，按核心关键词包含匹配 | 如"营业收入"可匹配"营业收入（合计）""营业收入(元)"等 |

### 5.3 字符清洗规则

在执行匹配前，对键名执行以下清洗操作：

```python
import re
import unicodedata

def clean_key(raw_key: str) -> str:
    """清洗财务软件导出的科目键名"""
    # 1. 去除 BOM 和零宽字符
    key = raw_key.replace('\ufeff', '').replace('\u200b', '').replace('\u200c', '')
    # 2. 全角空格转半角空格
    key = key.replace('\u3000', ' ')
    # 3. 全角引号转半角引号
    key = key.replace('\u201c', '"').replace('\u201d', '"')
    key = key.replace('\u2018', "'").replace('\u2019', "'")
    # 4. 去除首尾空格
    key = key.strip()
    # 5. NFC 规范化（处理 Unicode 组合字符）
    key = unicodedata.normalize('NFC', key)
    return key

def match_subject(raw_key: str, baseline_keys: list) -> str | None:
    """三级回退匹配科目键名"""
    # 第一级：精确匹配
    if raw_key in baseline_keys:
        return raw_key
    # 第二级：去空格匹配
    cleaned = clean_key(raw_key)
    cleaned_baseline = {clean_key(k): k for k in baseline_keys}
    if cleaned in cleaned_baseline:
        return cleaned_baseline[cleaned]
    # 第三级：关键词包含匹配
    core = re.sub(r'["\'\(\)\[\]（）【】「」.,，。、；;:：]', '', cleaned)
    for bl_cleaned, bl_original in cleaned_baseline.items():
        bl_core = re.sub(r'["\'\(\)\[\]（）【】「」.,，。、；;:：]', '', bl_cleaned)
        if core in bl_core or bl_core in core:
            return bl_original
    return None  # 未匹配，记录为新增科目
```

### 5.4 匹配结果记录

| 匹配级别 | 记录要求 |
|----------|----------|
| 第一级匹配成功 | 无需额外记录 |
| 第二级匹配成功 | 记录"键名含特殊字符，已自动清洗匹配"，日志中记录原始键名和清洗后键名 |
| 第三级匹配成功 | 记录"键名模糊匹配"，提示用户确认匹配正确性 |
| 匹配失败 | 记录为"新增科目（未匹配）"，触入口径一致性检查的"新增科目"流程 |

## 六、基线版本管理与更新

### 6.1 补充规则

1. **编码唯一**：每个科目编码在基线表中唯一，不可重复
2. **层级清晰**：一级科目为汇总科目，二级为明细科目，三级及以下按公司实际体系设置
3. **金额对应**：基线金额为最近一期已确认数据，后续分析以该期为基期
4. **变动留痕**：基线科目表每次更新需记录变更日志（变更时间、变更内容、变更原因、操作人）
5. **版本管理**：基线科目表采用版本号管理，格式为 `vX.Y`（X为主版本，科目体系重大调整时递增；Y为次版本，科目增删或金额更新时递增）

## 七、与技能 / 规则的衔接

```
数据导入    → 读本文件基线科目表 → 执行四级口径一致性检查 → 判定结果等级
STOP Gate   → 差异>20%或核心科目缺失 → 触发科目口径阻断 → 暂停分析等用户确认
键名匹配    → 读第五节三级回退规则 → 清洗特殊字符 → 逐级匹配 → 记录匹配结果
基线更新    → 用户确认科目变动 → 更新基线表 → 记录更新日志 → 版本号递增
```
