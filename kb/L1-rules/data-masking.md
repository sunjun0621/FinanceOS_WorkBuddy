# 脱敏标准清单

> 效力等级：L1 强制约束 · 红线不可违反
> 适用：FinanceOS 数据缓冲区入口 + 交付前 + 报送前
> 版本：v2 · 2026-07-31（整合 DuMate 12类脱敏标准 + 双方案机制 + 反推防护）
> 来源：WorkBuddy data-masking v1 + DuMate L1-Rules 01_脱敏标准清单 合并增强

---

## 一、总则

1. 脱敏范围按本清单执行，非每次自由确认
2. 用户可设"预设脱敏方案"——同类型操作自动执行，不再每次确认
3. 仅特殊场景（如报送需保留单位名称）才需逐次确认
4. 涉密文件不进入缓冲区，不处理
5. 本清单覆盖 12 类脱敏项，按风险等级分为最高、高、中三级

---

## 二、脱敏项与处理方式（12类）

| 序号 | 脱敏项 | 风险等级 | 标准处理方式 | 示例（脱敏前 → 脱敏后） |
|------|--------|----------|------------|--------------------------|
| 1 | 单位名称 | 高 | 替换为"本公司"或"某国企" | 某某集团某某公司 → 某国企 |
| 2 | 人名 | 高 | 替换为"某+职务"或岗位代号 | 张三 → 某财务总监 |
| 3 | 银行账号 | 最高 | 仅保留后4位，前缀用*号 | 6222021234567890 → ****7890 |
| 4 | 身份证号 | 最高 | 仅保留前3后4，中间用*号 | 530102199001011234 → 530****1234 |
| 5 | 合同编号 | 高 | 替换为"合同编号-序号" | HT-2026-001 → 合同编号-A |
| 6 | 金额（敏感） | 中 | 按场景替换为占位或保留（见双方案） | 见第四节 |
| 7 | 涉密文件 | 最高 | 禁止上传，仅记录文件名 | 不上传，标注"涉密文件-XX类" |
| 8 | 项目名称 | 中 | 替换为"项目-序号" | 某某基础设施工程 → 项目-A |
| 9 | 税号 | 高 | 仅保留前4后4，中间用*号 | 91530100MA6K1234X → 9153****234X |
| 10 | 地址信息 | 中 | 替换为"某市某区" | 某市某区某路某号 → 某市某区 |
| 11 | 联系方式 | 高 | 仅保留前3后4，中间用*号 | 13800138000 → 138****8000 |
| 12 | 内部文件文号 | 中 | 替换为"[内部文号]" | XX集团财字〔2026〕01号 → [内部文号] |

**金额处理说明**：
- 内部分析场景：金额可保留，仅脱敏单位和项目名称
- 对外报送场景：金额按区间替换（如 100万以下→"小额"、100-500万→"中额"、500万以上→"大额"）
- 涉密金额：绝对禁止上传，标注"涉密数据"并停止处理

## 三、行业专项脱敏项

> 以下为特定行业国企可能涉及的补充脱敏点，按行业特性选用。用户应根据本公司所属行业激活对应条目。

### 3.1 公用事业 / 管网类

| 脱敏项 | 标准处理方式 | 例外情况 |
|--------|------------|---------|
| 居民用量数据（水/气/热） | 不外发；内部分析时模糊化为区间 | 无例外（涉及用户隐私） |
| 工业用量数据 | 内部分析保留；对外报送模糊化 | 经财务总监确认可保留 |
| 管网坐标 / 走向 / 设施位置 | 不进入缓冲区，不处理 | 无例外（基础设施安全） |
| 价格监审材料 | 不进入缓冲区；如需分析，仅引用结论不引用过程 | 涉密等级高的不处理 |

### 3.2 城投 / 平台类

| 脱敏项 | 标准处理方式 | 例外情况 |
|--------|------------|---------|
| 化债注资信息 | 内部分析保留；对外报送按标准清单脱敏 | 涉密等级高的不进入缓冲区 |
| 城投平台关联信息 | 统一替换为"关联平台A""关联平台B" | 对外报送时经确认可保留 |
| 土地储备 / 出让信息 | 内部分析保留精确值；对外报送模糊化为区间 | 经财务总监确认可保留 |

### 3.3 通用补充

| 脱敏项 | 标准处理方式 | 例外情况 |
|--------|------------|---------|
| 供应商 / 客户名称（大额） | 替换为"供应商A""客户B" | 内部分析经确认可保留 |
| 银行名称及支行信息 | 替换为"开户行A" | 无例外 |
| 董事会 / 党委会决议内容 | 仅引用结论，不引用讨论过程 | 经确认可引用摘要 |

## 四、双方案机制

用户可设定预设方案，匹配任务类型自动套用：

### 方案A：内部分析方案

适用场景：用户上传数据供 AI 分析，分析结果仅用于内部决策参考，不对外报送。

| 脱敏项 | 处理规则 |
|--------|----------|
| 单位名称 | 保留（内部分析无需脱敏） |
| 人名 | 替换为"某+职务" |
| 银行账号 | 脱敏（保留后4位） |
| 身份证号 | 脱敏（保留前3后4） |
| 合同编号 | 替换为"合同编号-序号" |
| 金额 | 保留实际数值 |
| 涉密文件 | 禁止上传 |
| 项目名称 | 替换为"项目-序号" |
| 税号 | 脱敏（保留前4后4） |
| 地址信息 | 替换为"某市某区" |
| 联系方式 | 脱敏（保留前3后4） |
| 内部文件文号 | 保留 |

### 方案B：对外报送方案

适用场景：分析结果需对外报送（上级集团、国资委、行政单位等），或用户明确要求最高级别脱敏。

| 脱敏项 | 处理规则 |
|--------|----------|
| 单位名称 | 替换为"某国企"或"本公司" |
| 人名 | 替换为"某某某" |
| 银行账号 | 完全脱敏（全部替换为*号） |
| 身份证号 | 完全脱敏（全部替换为*号） |
| 合同编号 | 完全脱敏（替换为"合同-序号"） |
| 金额 | 按区间替换（小额/中额/大额） |
| 涉密文件 | 禁止上传 |
| 项目名称 | 完全脱敏（替换为"项目-序号"） |
| 税号 | 完全脱敏（全部替换为*号） |
| 地址信息 | 替换为"某市某区" |
| 联系方式 | 完全脱敏（全部替换为*号） |
| 内部文件文号 | 替换为"[内部文号]" |

### 方案匹配逻辑

- 任务类型为"内部分析 / 经营分析 / 预算编制" → 自动套用方案A
- 任务类型为"对外报送 / 上报材料 / 巡视汇报" → 自动套用方案B
- 仅特殊场景（如报送需保留单位名称）才逐次确认

## 五、反推防护（反推防护）

> 对外报送方案（方案B）须额外执行反推防护检查，防止通过多项信息的组合推断出单位真实身份。

### 5.1 反推风险说明

单项脱敏可能合规，但多项信息组合后仍可能暴露单位身份。例如：
- "某公益类国企" + "基础设施运输" + "某市" → 可缩小范围至特定企业
- "某国企" + "日处理能力XX万吨" + "某省" → 可精确定位具体单位

### 5.2 反推检查规则

| 检查维度 | 检查内容 | 处置方式 |
|----------|----------|----------|
| 行业特征组合 | 行业描述 + 地域 + 企业规模是否可唯一定位 | 模糊化行业描述或地域范围 |
| 经营数据组合 | 营收规模 + 员工人数 + 资产规模是否可反推 | 模糊化经营数据为更宽区间 |
| 业务特征组合 | 特定业务名称 + 地理位置 + 服务对象是否可识别 | 泛化业务描述 |
| 时间特征组合 | 特定事件时间 + 企业特征是否可关联 | 模糊化时间精度 |

### 5.3 反推检查执行时机

- 方案B交付前必须执行反推检查
- AI 助手在生成对外报送材料时，自动扫描是否存在可组合反推的信息
- 发现反推风险时，标注风险点并建议进一步模糊化

## 六、脱敏 gate 三环节

| 环节 | gate 内容 | 不可跳过的原因 |
|------|----------|--------------|
| 数据进入缓冲区前 | 按标准清单脱敏 | 防止敏感数据进入 AI 拥有的资源层 |
| 交付前 | 按标准清单确认脱敏范围 + 反推检查（方案B） | 最终交付物的安全边界 |
| 报送前 | 确认报送内容、格式、接收方 | 对外报送不可撤回 |

## 七、脱敏执行检查清单

### 7.1 上传前检查（每次上传文件必执行）

- [ ] 单位名称已替换（或方案A下保留）
- [ ] 人名已替换为职务代号或"某某某"
- [ ] 银行账号已脱敏（至少保留后4位）
- [ ] 身份证号已脱敏（至少保留前3后4）
- [ ] 合同编号已替换为序号代号
- [ ] 涉密文件已识别并禁止上传
- [ ] 项目名称已替换为序号代号
- [ ] 税号已脱敏（至少保留前4后4）
- [ ] 地址信息已替换为"某市某区"
- [ ] 联系方式已脱敏（至少保留前3后4）
- [ ] 内部文件文号已处理（方案A保留 / 方案B替换）

### 7.2 对外报送额外检查（方案B）

- [ ] 金额已按区间替换（不暴露精确数值）
- [ ] 银行账号/身份证号/税号已完全脱敏（全部*号）
- [ ] 项目名称已完全脱敏（仅保留"项目-序号"）
- [ ] 内部文件文号已替换为"[内部文号]"
- [ ] 反推检查已执行：无多项信息组合可反推单位身份

### 7.3 交付前最终检查

- [ ] 全文搜索确认无真实单位名称残留
- [ ] 全文搜索确认无真实人名残留
- [ ] 全文搜索确认无完整银行账号/身份证号/税号残留
- [ ] 确认涉密文件未被上传或包含在交付物中
- [ ] 确认地址信息已泛化为"某市某区"
- [ ] 确认联系方式已脱敏
- [ ] AI 助手中间处理过程中未将脱敏数据还原

## 八、残留数据清除规程

| 维度 | 规程 |
|------|------|
| 清理时机 | 任务完成后立即清理，不留过夜 |
| 清理范围 | 缓冲区内的原始数据文件 |
| 结论中的数据引用 | 允许引用分析结论（如"执行率 92%"）；不允许引用原始数据行（如"7月15日支付XXX公司50万元"） |
| 交付前检查 | 扫描产出文件，确认无原始数据残留 |
| 清理确认 | 记录清理时间和清理人，留痕可追溯 |

## 九、特殊说明

1. **脱敏不可逆**：脱敏处理一旦执行，不可逆向恢复原始数据。用户需在脱敏前自行备份原始文件
2. **涉密文件零容忍**：涉密文件绝对禁止上传 AI，无论脱敏与否。AI 遇到疑似涉密文件时应停止处理并提示用户
3. **路径脱敏**：所有文件路径中的真实目录名不包含真实单位信息，可在交付物中保留路径结构但替换敏感目录名
4. **方案切换**：用户可在任务开始时指定方案类型；未指定时，AI 助手按任务类型自动匹配

## 十、与技能 / 规则的衔接

```
数据上传    → 读本清单 → 识别任务类型 → 自动匹配方案A/B → 执行脱敏
分析处理    → 按方案A/B对应规则处理中间数据 → 不还原已脱敏信息
交付前      → 执行七节检查清单 → 方案B额外执行反推检查 → 确认无残留
报送前      → 确认报送内容/格式/接收方 → 最终脱敏确认
```
