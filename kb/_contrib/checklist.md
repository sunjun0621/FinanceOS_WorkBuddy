# 提交前自检清单 / Pre-Submission Checklist

在提交 PR 前，请逐项检查以下内容。

---

## 通用检查（所有库适用）

- [ ] 文件命名符合规范（见 [README.md](README.md#命名规范)）
- [ ] 元数据头完整（效力等级、适用、版本、日期、来源）
- [ ] 中文为主要语言
- [ ] 无特定企业 identifiable 信息（已脱敏）
- [ ] 无水印、无敏感数据
- [ ] 引用语法正确：`[L1:rule-name#anchor]`、`[L2:template-name]`、`[L3:case-name]`
- [ ] `[待用户补充]` 占位符用于需要用户自定义的值
- [ ] 版本记录已填写

---

## L1 规则附加检查

- [ ] 规则具有跨任务复用性（不是针对单次任务的指令）
- [ ] 判定标准明确、可执行（AI 能根据规则做出明确判断）
- [ ] STOP gate 联动条件已定义
- [ ] 与其他 L1 规则无冲突（如有冲突，注明优先级）
- [ ] 例外与豁免条件已说明

---

## L2 模板附加检查

- [ ] 模板结构完整（标题区 + 正文骨架 + 格式规范）
- [ ] 可被同类任务重复使用
- [ ] 调用说明已填写（触发条件 + 执行流程）
- [ ] 质量检查清单已包含
- [ ] 格式规范引用 [L2:gb-t9704-spec]（如适用）

---

## L3 案例附加检查

- [ ] 来源标签已标注：`[提炼]`（经验证可复用）或 `[原文]`（未验证）
- [ ] "问题"部分清晰（要解决什么、验证什么）
- [ ] "方法"部分可复现（步骤明确、依据可查）
- [ ] "可复用要点"至少 3 条
- [ ] 数据来源已注明（模拟/实际已脱敏/公开）

---

## PR 规范

- [ ] PR 标题格式：`[KB-L1] 新增：规则名称` / `[KB-L2] 新增：模板名称` / `[KB-L3] 新增：案例名称`
- [ ] PR 描述包含：影响范围、适用行业、测试情况
- [ ] 一个 PR 只包含一个条目（便于评审）
